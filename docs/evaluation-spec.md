# 评测规范 (Evaluation Specification)

RootCause Agent 评测规范 —— 对标 LogDx-CI（FSE 2025）、RCAEval（FSE 2024）及学术评测最佳实践，
规定"如何评测一个日志压缩/根因定位方案"，保证结果公平、可复现、可审计、可比较。

---

## 1 目的与适用范围

本规范适用于：对"面向 LLM 根因定位的上下文压缩方案"进行横向评测的全部活动，包括数据集使用、
方法接入、判分、结果报告与复现。任何引用本项目的评测结论必须遵循本规范。

## 2 术语

| 术语 | 定义 |
|---|---|
| 压缩率 | token 压缩率：`1 - 压缩后token/原始token`（token 估算 `len(chars)//2`） |
| 召回率 | 压缩输出包含 ground-truth 信号的比例（LogDx-CI 静态信号召回） |
| AC@k | top-k 命中率（RCAEval 官方口径） |
| reducer | 压缩函数：`raw_log → compressed_text`（LogDx-CI 协议） |
| 方法 | 参与对比的压缩/定位方案 |

## 3 数据集规范

### 3.1 数据集准入

- 必须使用**业界公开、带 ground-truth 标注**的数据集，优先：RCAEval（FSE 2024）、LogDx-CI（FSE 2025）；
- 自建数据集必须：标注根因（服务/信号）、公开或随项目分发、声明构建方式；
- 禁止使用评测集做方法调参（见 5.4）。

### 3.2 划分与使用

- 全量评测：数据集全量 case 必须全部评测，禁止抽样后外推（如 RE1 全量 125、RE3 全量 90）；
- 子集评测：必须声明子集选取规则（如"每 服务×故障 取 1"）且注明子集规模；
- 数据缺陷 case（损坏的标注文件）跳过时必须记录并标注（如 re1ob currencyservice_loss_1 inject_time 损坏）。

### 3.3 下载与版本

- 记录数据来源 URL、版本（zip 名/HF commit）、本地路径；
- 数据文件哈希可选但推荐记录。

## 4 评测流程规范

### 4.1 环境

- 记录：硬件、OS、Python 版本、venv、LLM 模型与参数（temperature、max_tokens）；
- LLM 参数必须固定（温度 0），变更需重新评测。

### 4.2 方法接入

- 所有方法使用**同一评测 harness**（同一判分代码、同一输入输出协议）；
- 竞品必须使用**真实能力**：禁止降级/截断冒充（headroom 必须用真实 Kompress 而非截断 fallback）；
- 方法输出超上下文限制时统一截断规则并**标注"受限"**（如 raw 110K chars 截断）；
- 竞品依赖缺失（模型下载失败、网络阻塞）时如实标注"不可运行"，禁止编造结果。

### 4.3 公平性

- 同一 LLM 判分（多方法共用时）或同一判分协议（静态评测时）；
- 多源数据（日志+追踪+指标）：共享部分（traces/metrics 摘要）对全方法一致，差异仅限被评测的组件；
- 控制 token 预算：各方法输出预算一致（或声明差异）。

### 4.4 判分

- 静态评测（LogDx-CI）：官方 `logdx_ci.evaluate`，确定性评分；
- RCAEval：官方 Evaluator（AC@1/AC@3/Avg@5）；
- LLM 判分（自建）：ground-truth 比对，禁止让同一 LLM 既压缩又判分。

## 5 指标规范

### 5.1 必报指标

横向评测**必须双指标并出**：

1. **正确率/召回率**（准确率、AC@1、信号召回率）；
2. **token 压缩率**（或 token 消耗绝对值 + 原始量）。

禁止只报单一指标（如只报压缩率不报准确率，或反之）。

### 5.2 口径

- token 估算统一 `len(text)//2`；若用真实 tokenizer 必须声明；
- 压缩率基准（原始量）必须声明（原始日志全量 / 多源全量）；
- 分系统报告（RCAEval 按系统/数据集分别报告，禁止混合掩盖差异）。

### 5.3 排名

- 双指标分别排名（准确率排名 + 压缩率排名）；
- 并列处理：相同值取同名次。

### 5.4 防泄漏

- 评测集不得用于超参调优（调优必须用验证集/消融集，如 LogDx-CI 与 RE3 分开使用）；
- 本项目中：LogDx-CI 用于压缩器参数回归，RE3 用于定位能力验证 —— 两集不互作调优集；
- 报告必须声明哪些数据集参与了调优。

## 6 基线规范

- 至少包含：不压缩基线（raw/full）、业界代表性方案（rtk/headroom/drain 等）、数据集官方 baseline（RCAEval main.py 方法）；
- 基线版本锁定并记录（如 rtk 0.44.2、headroom-ai 0.33.0 + kompress-v2-base）；
- 论文对照值必须标注来源（论文名/页码/表号），且优先本地实测替代论文值。

## 7 可复现性规范

- 评测工程开源（eval-project/），包含：数据下载脚本、评测脚本、结果解析、README；
- 随机性：LLM 温度 0；静态评测零随机；
- 波动处理：LLM 判分维度多次运行（≥3 轮）报告均值与范围（如 re1ob 3 轮 100%±0）；
- 结果存储：原始输出（pred/score）落盘 JSON，禁只存汇总数字；
- 环境记录：venv 依赖清单（requirements/pyproject）。

## 8 报告规范

- 表格必含：方法、指标值、名次、case 数；
- 不可运行/受限/降级的方案必须显式标注（如 LLMLingua：网络阻塞不可运行）；
- 数据缺陷 case 跳过须记录；
- 结论必须与数据一致：禁止选择性报告"对自己有利"的指标（自嗨禁令）。

## 9 质量控制

- 代码改动后必须回归：LogDx-CI 静态评分（确定性）、RE3 关键子集重跑；
- 每次改动记录 A/B 对比（消融表）；
- 评测脚本 bug 修复后重跑受影响维度（如 re1ob 路径解析 bug 修复后重跑 125 case）；
- 发布前核对：全部表格数字与结果文件一致。
